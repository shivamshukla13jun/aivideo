# Project notes

- Dev server: `npm run dev` (port 5000). Next.js 15 App Router, Mongoose, Tailwind.
- Content source: user uploads — series created via `POST /api/series` (multipart), chapters via `POST /api/chapters` (JSON body, no file). NO Suwayomi anymore. CBZ extraction happens client-side (`lib/cbzClient.ts` uses JSZip in browser); pages upload one-by-one via `POST /api/chapters/[id]/pages` (multipart single image), then `POST /api/chapters/[id]/finalize` marks chapter `ready`.
- Storage: MinIO (`lib/minio.ts`). `uploadFile()` stores buffers, `fileUrl(key)` → `/api/files/<key>` (same-origin stream route — keeps canvas untainted). `lib/cbz.ts` extracts page images with jszip and uploads archive+pages to `chapters/<id>/`.
- `Page.publicId` holds the MinIO object key; `originalUrl`/`editedUrl` hold `/api/files/...` URLs. OCR reads buffers straight from MinIO.
- Scene audio shape: `{ url, objectKey, duration, format, fileSize }` (`cloudinaryUrl`/`publicId` remain for legacy docs).
- Typecheck: `npx tsc --noEmit -p .` (ignore stale errors under `.next/types` for deleted routes).
- Lint: `npx eslint <files>` (`<img>` warnings are expected project-wide).
- Video: Remotion (`remotion`, `@remotion/player`, `@remotion/web-renderer`, `@remotion/media`, `@remotion/transitions`, pinned 4.0.526).
  - Composition: `components/video/WebtoonVideo.tsx`; camera math shared by preview/editor/export in `lib/video/camera.ts`; scene → props in `lib/video/project.ts`.
  - Scene clean-up (`lib/video/cleanup.ts`): `cuts` (full-width bands removed, content closes up) and `hideBoxes` (blur/black/white), in fractions of the ORIGINAL image. Camera coordinates are in the cleaned image space (`effectiveImageHeight`). `components/video/CleanedImage.tsx` renders the cleaned image for both the composition and the editor.
  - Subtitles: English (`narration`) + Hindi (`narrationHi`) stacked, chunked & timed by `lib/video/subtitles.ts`.
  - Camera presets: `read-down`, `read-up`, `slideshow` (steps easing — holds each viewport then slides to next; `camera.steps` = screen count), `hold`, `zoom-in`, `zoom-out`, `full-page`, `pan-left`, `pan-right`, `diagonal-dr`, `diagonal-dl`, `dolly-in`, `crane-down`, `focus-pull`, `orbit`, `whip-pan`, `drift`. Easings: `linear`, `ease-in-out`, `ease-out`, `ease-in`, `steps`.
  - Apply-to-all: CameraEditor "Apply presets to all N scenes" toggle recomputes the preset per-page via `presetCamera`; Layers buttons beside Duration/Transition/Camera FX/Visual FX apply that field to every scene (`applyFieldToAllScenes` in studio page). Remove Parts tab has "Auto-cut blank gaps on all N scenes" (`autoCutBlankGapsAll`) — runs `detectBlankGaps` per page, merges cuts, refits duration+camera.
  - Camera FX (per-frame): `none`, `shake`, `pulse`, `float`, `heartbeat`, `zoom-pulse`, `breathe`.
  - Visual FX (overlay): `none`, `vignette`, `speed-lines`, `bloom`, `flash`, `sepia`, `high-contrast`, `letterbox`, `film-grain`, `rain`, `particles`, `noir`, `color-wash-warm`, `color-wash-cool`, `focus-blur`, `manga-tone`.
- OCR (`lib/ocr.ts`): single provider `paddle` — self-hosted PaddleOCR sidecar (`ocr-server/`, docker-compose `paddleocr` service, `PADDLEOCR_URL`, default http://localhost:5004). Server `/ocr` pipeline: light prep (border cleanup, CLAHE, sharpen) → strip-splits pages >2200px tall (160px overlap) → inverted second pass on dark pages → dedupe → bubble grouping. Env knobs: `PADDLE_OCR_MODEL=server|mobile` (default `server`, more accurate), `OCR_MIN_SCORE` (default 0.5), `OCR_STRIP_HEIGHT`/`OCR_STRIP_OVERLAP`. Hindi translation (`translateText`, `/api/translate`, OCR pipeline `narrationHi`): prefers Gemini (`GEMINI_API_KEY`, gemini-2.5-flash) for colloquial Mumbai-style spoken Hindi — Hinglish loanwords transliterated to Devanagari, no literary Hindi, untranslatable words left as-is; falls back to OCR server `/translate` (deep-translator Google→MyMemory, sentence-chunked, free, no API key). Gemini is also used for SEO (`/api/social/seo`, `/api/youtube/seo`); not used for OCR. Jobs store `provider` + `overwriteScenes` (re-extract). Pages store `extractedText` (EN), `extractedTextHi`, `ocrRaw`, `ocrProvider`.
  - Image preprocessing: `POST /api/chapters/[id]/preprocess` sends pages to the OCR server's `/preprocess` endpoint (denoise, CLAHE, watermark removal, border cleanup, text sharpening), saves cleaned images back to MinIO as `editedUrl`.
  - Run OCR server without Docker: `cd ocr-server && python -m venv .venv && .venv\Scripts\Activate.ps1 && pip install -r requirements.txt && uvicorn server:app --port 5004`.
- Deletion: `DELETE /api/chapters/[id]` cascade-deletes pages, scenes, OCR jobs, and MinIO objects. `DELETE /api/series/[id]` cascade-deletes all chapters + series data + library entries. Both require confirmation in the UI.
  - Remote images must go through `/api/proxy-image` (`toVideoSrc`) so the browser renderer can draw them to canvas.
  - Client-side rendering only supports a subset of CSS (no mix-blend-mode, backdrop-filter, radial gradients, inset shadows, z-index).
- Studio auto-save: OFF by default. Toggle in header. Manual "Save" button appears when there are unsaved changes. Persisted in localStorage.
- Multi-platform publishing (`/distribute` + `MultiPlatformPublishPanel` in Studio):
  - `lib/social/` — per-platform libs implementing `SocialPlatformLib` (types.ts): `instagram.ts` (Graph API Reels via linked FB Page), `reddit.ts` (OAuth 2.0 `identity submit` + media-lease/S3 upload + `api/submit` kind=video; posts to `u_<user>` profile by default, override via `platformMeta.subreddit`; requires `User-Agent`), `twitter.ts` (OAuth 2.0 PKCE-S256 + chunked media upload), `facebook.ts` (resumable video upload to Pages). `index.ts` exposes `getPlatformLib()`.
  - Models: `SocialAccount` (platform + platformUserId unique pair, tokens in `platformMeta` e.g. `pageAccessToken`), `SocialUpload` (cross-platform upload record w/ per-target status).
  - API: `GET /api/social/auth?platform=`, `GET /api/social/auth/callback/[platform]`, `GET/DELETE /api/social/accounts`, `POST /api/social/accounts/[id]/sync`, `POST /api/social/upload` (multipart, handles YouTube + social targets in one doc), `GET /api/social/uploads`, `POST /api/social/seo`, `POST /api/social/shorts`.
  - Env vars: `FACEBOOK_APP_ID`/`FACEBOOK_APP_SECRET` (covers Instagram too), `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET` (+ optional `REDDIT_USER_AGENT`), `TWITTER_CLIENT_ID`/`TWITTER_CLIENT_SECRET`, plus existing `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`.
  - Advanced SEO (`lib/social/seo.ts`): `generateAdvancedSeo` = algorithmic (tone detection, keyword extraction, viral title patterns, virality scoring, platform-specific captions, posting schedule); `enhanceSeoWithAI` layers Gemini on top when `GEMINI_API_KEY` is set.
  - Shorts generator (`lib/social/shorts.ts`): `generateShortClips` scores scenes (action keywords, dialogue, audio, position) and emits clip strategies (hook-highlight, action-sequence, cliffhanger, best-moments, full-recap); `platformMaxDuration` returns the strictest duration limit across target platforms. Clips render client-side via the same Remotion composition.
