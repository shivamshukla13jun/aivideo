# Project notes

- Dev server: `npm run dev` (port 5000). Next.js 15 App Router, Mongoose, Tailwind.
- Content source: user uploads — series created via `POST /api/series` (multipart), chapters via `POST /api/chapters` (JSON body, no file). NO Suwayomi anymore. CBZ extraction happens client-side (`lib/cbzClient.ts` uses JSZip in browser); pages upload one-by-one via `POST /api/chapters/[id]/pages` (multipart single image), then `POST /api/chapters/[id]/finalize` marks chapter `ready`.
- Storage: MinIO (`lib/minio.ts`). `uploadFile()` stores buffers, `fileUrl(key)` → `/api/files/<key>` (same-origin stream route — keeps canvas untainted). `lib/cbz.ts` extracts page images with jszip and uploads archive+pages to `chapters/<id>/`.
- `Page.publicId` holds the MinIO object key; `originalUrl`/`editedUrl` hold `/api/files/...` URLs. OCR reads buffers straight from MinIO.
- Scene audio shape: `{ url, objectKey, duration, format, fileSize }` (`cloudinaryUrl`/`publicId` remain for legacy docs).
- Typecheck: `npx tsc --noEmit -p .` (ignore stale errors under `.next/types` for deleted routes).
- Lint: `npx eslint <files>` (`<img>` warnings are expected project-wide).
- Video: Remotion (`remotion`, `@remotion/player`, `@remotion/web-renderer`, `@remotion/media`, `@remotion/transitions`, pinned 4.0.526).
  - Composition: `components/video/WebtoonVideo.tsx`; camera math shared by preview/editor/export in `lib/video/camera.ts`; scene → props in `lib/video/project.ts`.
  - Scene clean-up (`lib/video/cleanup.ts`): `cuts` (full-width bands removed, content closes up) and `hideBoxes` (blur/black/white), in fractions of the ORIGINAL image. Camera coordinates are in the cleaned image space (`effectiveImageHeight`). `components/video/CleanedImage.tsx` renders the cleaned image for both the composition and the editor.
  - Subtitles: English (`narration`) + Hindi (`narrationHi`) stacked, chunked & timed by `lib/video/subtitles.ts`.
  - Camera presets: `read-down`, `read-up`, `slideshow` (steps easing — holds each viewport then slides to next; `camera.steps` = screen count), `hold`, `zoom-in`, `zoom-out`, `full-page`, `pan-left`, `pan-right`, `diagonal-dr`, `diagonal-dl`, `dolly-in`, `crane-down`, `focus-pull`, `orbit`, `whip-pan`, `drift`. Easings: `linear`, `ease-in-out`, `ease-out`, `ease-in`, `steps`.
  - Apply-to-all: CameraEditor "Apply presets to all N scenes" toggle recomputes the preset per-page via `presetCamera`; Layers buttons beside Duration/Transition/Camera FX/Visual FX apply that field to every scene (`applyFieldToAllScenes` in studio page). Remove Parts tab has "Auto-cut blank gaps on all N scenes" (`autoCutBlankGapsAll`) — runs `detectBlankGaps` per page, merges cuts, refits duration+camera. It also auto-runs silently after "Process Images" finishes and when pages are added as scenes.
  - Camera FX (per-frame): `none`, `shake`, `pulse`, `float`, `heartbeat`, `zoom-pulse`, `breathe`.
  - Visual FX (overlay): `none`, `vignette`, `speed-lines`, `bloom`, `flash`, `sepia`, `high-contrast`, `letterbox`, `film-grain`, `rain`, `particles`, `noir`, `color-wash-warm`, `color-wash-cool`, `focus-blur`, `manga-tone`.
  - Transitions (`Scene.transition`, `TRANSITION_OPTIONS` in `lib/video/project.ts`): `none`, `fade`, `dissolve`, `slide`, `wipe`, `push-cut`, `blur-slide`, `linear-blur`, `cross-zoom` (Zoom Punch), `zoom-in-out`, `iris`, `flip`. cross-zoom/zoom-in-out/linear-blur/blur-slide are WebGL shader presentations (html-in-canvas). New scenes get `studio-default-transition` (localStorage, default `cross-zoom`) — picker under the Add Pages button; per-scene picker in the editor; Layers button applies to all.
  - Style Presets (`STYLE_PRESETS` in studio page): one-click combos of camera preset + camera FX + visual FX + transition (Recap, Cinematic, Action, Dramatic, Dreamy, Slideshow) — click previews on the active scene, "all" applies to every scene.
  - Page ops (studio hover tools): split a page at a cut line (`POST /api/chapters/[id]/pages/[pageId]/split`, sharp slice → top keeps the Page doc, bottom inserts at order+1 with later orders shifted, OCR fields cleared, scenes repointed, original object deleted); reorder via `PUT /api/chapters/[id]/pages/reorder` (hover ↑/↓); insert new image via pages POST `insert=true` (shifts orders ≥ slot) — grid "Add image" tile appends.
- OCR (`lib/ocr.ts`): single provider `paddle` — self-hosted PaddleOCR sidecar (`ocr-server/`, docker-compose `paddleocr` service, `PADDLEOCR_URL`, default http://localhost:5004). Server `/ocr` pipeline: light prep (border cleanup, CLAHE, sharpen) → strip-splits pages >2200px tall (160px overlap) → inverted second pass on dark pages → dedupe → bubble grouping. Env knobs: `PADDLE_OCR_MODEL=server|mobile` (default `server`, more accurate), `OCR_MIN_SCORE` (default 0.5), `OCR_STRIP_HEIGHT`/`OCR_STRIP_OVERLAP`. The PaddleOCR engine warms up in a background thread at startup (auto-downloads models on first run, 3 retries) — watch for `[ocr] PaddleOCR engine ready` in the console. Hindi translation (`translateText`, `/api/translate`, OCR pipeline `narrationHi`): prefers the active AI provider via `lib/ai.ts` `generateAIText` — provider picked at `/settings` or the navbar toggle (Setting doc `aiProvider`, default `gemini`), falls back to the other provider. Gemini (`lib/gemini.ts`) walks a key × model chain (next MODEL on 503/404, next KEY on 429/auth-reject; invalid keys auto-disable) — keys + model order client-managed in Mongo (`GeminiKey` collection masked via `/api/settings/gemini`, `Setting` doc `geminiModels`, defaults `gemini-3.8-flash` → 3.7 → 3.6 → 3.5 → 3.5-lite → 3.1-lite → `gemini-flash-lite-latest`). Ollama (`lib/ollama.ts`, `OLLAMA_URL` default http://localhost:11434) walks its own model chain (`Setting` doc `ollamaModels`, first = default, defaults `llama3.2:latest` → `qwen3:4b` → `gemma3:4b`) and auto-pulls missing models via `ollama pull` — progress tracked and shown live at `/settings` (`/api/settings/ollama` + `/api/settings/ollama/pull` NDJSON stream) for colloquial Mumbai-style spoken Hindi — Hinglish loanwords transliterated to Devanagari, no literary Hindi, untranslatable words left as-is; falls back to OCR server `/translate` (deep-translator Google→MyMemory, sentence-chunked, free, no API key). Gemini is also used for SEO (`/api/social/seo`, `/api/youtube/seo`); not used for OCR. All heavy pipeline ops run as `OcrJob`s on the shared `ocr.extract` RabbitMQ queue (worker prefetch=1 → jobs run serially; sync fallback inside `runOcrJob` when the broker is down). Jobs store `provider`, `stage` (`'preprocess'` = image cleanup via `POST /api/chapters/[id]/preprocess`, `'extract'` = OCR→EN via `extract-ocr`, `'translate'` = EN→HI via `translate-text`) + `overwriteScenes` (re-run). All stages are resumable — pages that already have the stage's output (`processedKey`/`ocrProvider`/`extractedTextHi`) are skipped, so re-running after a reload continues on pending pages only; retries process `failedOrders` only. Studio polls `/api/ocr-jobs?chapterId=` every 5s for progress/completion (also reattaches after reload). Ollama generation/pulls stream with undici timeouts disabled (`unlimitedFetchInit` in `lib/ollama.ts`) — CPU models can take unlimited time. Pages store `extractedText` (EN), `extractedTextHi`, `ocrRaw`, `ocrProvider` (presence = extraction done).
  - Image preprocessing: `POST /api/chapters/[id]/preprocess` sends pages to the OCR server's `/preprocess` endpoint (denoise, CLAHE, watermark removal, border cleanup, text sharpening), saves cleaned images as `<name>_processed.png`, repoints the Page (`originalUrl`/`editedUrl`/`publicId`/`processedKey`) and matching scenes at it, and deletes the old objects — only the processed file is kept.
  - Run OCR server without Docker: `cd ocr-server && python -m venv .venv && .venv\Scripts\Activate.ps1 && pip install -r requirements.txt && uvicorn server:app --port 5004`.
- Deletion: `DELETE /api/chapters/[id]` cascade-deletes pages, scenes, OCR jobs, and MinIO objects. `DELETE /api/series/[id]` cascade-deletes all chapters + series data + library entries. Both require confirmation in the UI.
  - Remote images must go through `/api/proxy-image` (`toVideoSrc`) so the browser renderer can draw them to canvas.
  - Client-side rendering only supports a subset of CSS (no mix-blend-mode, backdrop-filter, radial gradients, inset shadows, z-index).
- Studio auto-save: OFF by default. Toggle in header. Manual "Save" button appears when there are unsaved changes. Persisted in localStorage.
- Multi-platform publishing (`/distribute` + `MultiPlatformPublishPanel` in Studio):
  - `lib/social/` — per-platform libs implementing `SocialPlatformLib` (types.ts): `instagram.ts` (Graph API Reels via linked FB Page), `reddit.ts` (OAuth 2.0 `identity submit` + media-lease/S3 upload + `api/submit` kind=video; posts to `u_<user>` profile by default, override via `platformMeta.subreddit`; requires `User-Agent`), `twitter.ts` (OAuth 2.0 PKCE-S256 + chunked media upload), `facebook.ts` (resumable video upload to Pages). `index.ts` exposes `getPlatformLib()`.
  - Models: `SocialAccount` (platform + platformUserId unique pair, tokens in `platformMeta` e.g. `pageAccessToken`), `SocialUpload` (cross-platform upload record w/ per-target status).
  - API: `GET /api/social/auth?platform=`, `GET /api/social/auth/callback/[platform]`, `GET/DELETE /api/social/accounts`, `POST /api/social/accounts/[id]/sync`, `POST /api/social/upload` (multipart, handles YouTube + social targets in one doc), `GET /api/social/uploads`, `POST /api/social/seo`, `POST /api/social/shorts`.
  - Env vars: `FACEBOOK_APP_ID`/`FACEBOOK_APP_SECRET` (covers Instagram too), `REDDIT_CLIENT_ID`/`REDDIT_CLIENT_SECRET` (+ optional `REDDIT_USER_AGENT`), `TWITTER_CLIENT_ID`/`TWITTER_CLIENT_SECRET`, plus existing `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`.
  - Advanced SEO (`lib/social/seo.ts`): `generateAdvancedSeo` = algorithmic (tone detection, keyword extraction, viral title patterns, virality scoring, platform-specific captions, posting schedule); `enhanceSeoWithAI` layers Gemini on top when a key is configured in `/settings`.
  - Shorts generator (`lib/social/shorts.ts`): `generateShortClips` scores scenes (action keywords, dialogue, audio, position) and emits clip strategies (hook-highlight, action-sequence, cliffhanger, best-moments, full-recap); `platformMaxDuration` returns the strictest duration limit across target platforms. Clips render client-side via the same Remotion composition.
